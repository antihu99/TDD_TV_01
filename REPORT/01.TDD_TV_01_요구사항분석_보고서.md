## 1. 보고서 개요

본 문서는 **시니어 Java QA 엔지니어** 관점에서 `README.md` 및 `.cursorrules`를 기준으로 TDD_TV 프로젝트 요구사항을 분석한 결과를 요약합니다.

분석 목적은 Controller 모듈(`TVController`) TDD 착수 전에 **비즈니스 규칙·API 계약·경계값·테스트 백로그**를 명확히 하는 것입니다. 상세 표·시나리오 32건은 [`docs/requirements_analysis.md`](../docs/requirements_analysis.md)에 정리되어 있으며, 본 보고서는 의사결정·현황·후속 작업에 필요한 핵심만 담습니다.

> **참고**: 프롬프트에서 언급된 `TddTvRequirements.txt`는 저장소에 존재하지 않아, **`README.md` 요구사항 정의 절**을 단일 기준 문서로 사용했습니다.

## 2. 분석 범위 및 방법

### 2.1 분석 범위

| 구분 | 포함 | 제외 |
|------|------|------|
| 도메인 | 리모컨 키, 채널 0~99, 선호채널, 채널검색, 업/다운 | Tuner 내부 구현 |
| 모듈 | `TVController`, `remoteKey`, `Tuner` 인터페이스 사용 | Gilded Rose 등 타 프로젝트 |
| 테스트 | `TVControllerTest` 백로그, `TunerTest` 계약 참고 | Tuner 구현체 단위 테스트 작성 |

### 2.2 분석 방법

1. `README.md` — TDD_TV, TDD practice 절에서 기능·시나리오 추출  
2. `Tuner.java` / `TunerTest.java` — 외부 API 계약·유효/무효 채널 패턴 확인  
3. `TVController.java` / `remoteKey.java` — 현재 구현 대비 갭 분석  
4. `.cursorrules` — 테스트 작성 원칙(GWT, Parameterized, Mock/Fake) 반영  
5. 규칙 ID 부여(C-, N-, UD-, S-, F-, P-)로 추적 가능하도록 문서화

## 3. 도메인 요약

### 3.1 공통 규칙

| ID | 규칙 |
|----|------|
| C-01 | 일반 채널 **0 ~ 99** |
| C-02 | 숫자 키 **0 ~ 9** 만 채널 입력 |
| C-03 | `Tuner`는 정확 동작 가정, 테스트는 **Mock/Fake** |
| C-04 | 리모컨 입력은 **`remoteKey` 등 키 값**으로 Controller에 전달 |

### 3.2 기능별 규칙 요약

| 기능 | 핵심 규칙 | 규칙 ID 예 |
|------|-----------|------------|
| 숫자 + 확인 | `1`+확인→1, `1`+`2`→12, 연속 4자리→12 후 34, `4`+`5`+`6`→45 후 확인/기타키 분기 | N-01 ~ N-07 |
| 채널 업/다운 (검색 없음) | ±1, 99↔0 순환 | UD-01 ~ UD-04 |
| 채널 업/다운 (검색 있음) | 저장 목록 기준 이전/다음, 목록 밖은 순환 | UD-05 ~ UD-08 |
| 채널 검색 | `seekCH()` 반복으로 목록 저장 | S-01 ~ S-03 |
| 선호 채널 추가 | 미등록→추가, 등록됨→삭제(토글) | F-01, F-02 |
| 다음 선호 채널 | 현재보다 큰 선호 중 최소, 없으면 최소 선호로 로테이션 | P-01 ~ P-03 |

## 4. `Tuner` API 계약 (Controller 협력 객체)

| 메소드 | 역할 | Controller 사용 |
|--------|------|-----------------|
| `seekCH()` | 증가 방향 시청 가능 채널 검색·변경·반환 | 채널검색 버튼 |
| `setCH(String ch)` | 지정 채널 설정 (무효 시 `IllegalArgumentException`) | 숫자·확인, 업/다운, 선호 이동 |
| `getCurrentCH()` | 현재 채널 반환 | Given/Then 검증 |

### 4.1 경계값 (`TunerTest` 기준)

| 구분 | 입력 예 | 기대 |
|------|---------|------|
| 유효 | 0, 4, 5, 12, 99 | 설정 성공 |
| 무효 | -12, -2, 100, 9999 | `IllegalArgumentException` |
| seekCH | 연속 호출 | 반환값 0~99, null 아님 |

## 5. Controller 모듈 — README 기대 vs 현재 구현

### 5.1 README 기준 Controller 담당 기능

| # | 기능 | 상태 |
|---|------|------|
| 1 | 숫자 버튼 채널 변경 (버퍼·확인·연속 입력) | 미구현 |
| 2 | 선호 채널 추가 (토글) | 미구현 |
| 3 | 다음 선호 채널 | 미구현 |
| 4 | 채널 검색 (`seekCH` 목록 저장) | 미구현 |
| 5 | 업/다운 (검색 없음) | 미구현 |
| 6 | 업/다운 (검색 있음) | 미구현 |
| 7 | `pushButton(remoteKey)` 단일 진입점 | **부분 구현** |
| 8 | `Tuner` 연동 (`setCH` 등) | **미연동** (주석 처리) |

### 5.2 현재 코드 갭

| 항목 | 현재 | 필요 |
|------|------|------|
| `remoteKey` | `KEY_1`, `KEY_OK` | 0~9, 업/다운, 검색, 선호, 다음선호 |
| `TVController` | `KEY_1` 누적, 확인 시 로그만 | `tuner.setCH` 및 전 기능 분기 |
| 검증 | `System.out` | Mockito `verify` / `getCurrentCH` |

## 6. 테스트 현황 (2026-05-19)

```
mvn test
Tests run: 14, Failures: 10, Errors: 1, Skipped: 2
```

| 클래스 | 결과 | 비고 |
|--------|------|------|
| `TVControllerTest` | 통과 | 스켈레톤 수준 |
| `TunerTest` | 10 실패, 1 오류 | Mock stub 미설정 — **API 참고용** |

**해석**: `TunerTest` 실패는 Tuner 미구현이 아니라 **Mock 기본 동작** 때문이다. Controller TDD는 `TVControllerTest` + `FakeTuner` 또는 적절히 stub된 Mock으로 진행하는 것이 `.cursorrules`와 일치한다.
