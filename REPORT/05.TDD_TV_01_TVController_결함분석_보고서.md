## 4. `TVController` 결함 위치 특정

### 4.1 현재 코드 — 결함 없음

핵심 분기는 요구사항·테스트와 일치합니다.

| 시나리오 | 관련 규칙·테스트 | 파일:줄 | 역할 |
|----------|------------------|---------|------|
| 숫자 키 → 버퍼만 | N-02~04 | `TVController.java:33-35` | digit early return |
| OK → 확정 후 clear | N-05, OK-02 | `38-40`, `51-55` | OK는 clear **이전** 처리 |
| 비숫자·비OK → 버퍼 무효화 | N-06, X-02, X-01 | **`43`** | `channelBuffer.clear()` |
| 검색 없음 UP/DOWN | UD-01~04 | `58-71`, `94-101` | `wrapChannel` |
| 검색 목록 UP/DOWN | UD-05~08, X-03 | `60-62`, `68-70` | `ScannedChannelList` |
| 선호 다음 | P-01~04 | `82-83` | `FavoriteChannels` |

```java
public void pushButton(remoteKey key) {
    if (key.isDigitKey()) {
        channelBuffer.appendDigit(key.getKeyValue());
        return;
    }
    if (key == remoteKey.KEY_OK) {
        confirmChannelFromBuffer();
        return;
    }
    channelBuffer.clear();  // ← N-06, X-02 등 회귀 방지 핵심

    RemoteKeyHandler handler = keyHandlers.get(key);
    if (handler != null) {
        handler.handle(this);
    }
}
```

## 6. 최소 수정 방안

### 6.1 현재 — 프로덕션 수정 불필요

`TVController`·협력 클래스(`ChannelInputBuffer` 등)에 **추가 diff 없이 Green** 상태입니다.  
`Item` 클래스는 저장소에 없으며, **수정 대상에서 제외**합니다.

### 6.2 과거 테스트 측 최소 diff (참고)

**S-02**

```diff
- when(tuner.seekCH()).thenReturn("14", "4", "6");
+ when(tuner.seekCH()).thenReturn("14", "4", "6", "14", "4", "6");
```

**B-CH-07** — 단일 테스트를 07a·07b로 분리 (04 보고서 §8 참고).

### 6.3 가상 회귀 시 최소 프로덕션 diff

43행 `channelBuffer.clear()`가 누락된 경우 **한 줄 복구**로 N-06·X-02 등 다수 시나리오 복구.

```diff
     if (key == remoteKey.KEY_OK) {
         confirmChannelFromBuffer();
         return;
     }
+    channelBuffer.clear();
     RemoteKeyHandler handler = keyHandlers.get(key);
```

## 10. 결론

`TVControllerTest` **45건 전부 Green**이며, Surefire에 **실패 로그가 없습니다.**  
과거 Red는 **S-02·B-CH-07의 Mockito 스텁 설계**에서 발생했고, 테스트 보강으로 해결되었습니다.  
`TVController.pushButton`의 **43행 버퍼 클리어**와 **38~40행 OK 선처리**가 회귀 방지의 핵심이며, 현재 구현은 요구사항과 일치합니다.

프로덕션 코드 추가 수정은 **불필요**하며, 회귀 방지는 `mvn test -Dtest=TVControllerTest` 및 `mvn clean verify`로 확인합니다.
