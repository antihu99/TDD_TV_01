## 1. 목적·범위

### 1.1 목적

- 리모컨 입력 → 채널 상태 전이 → `Tuner.setCH` / `seekCH` 연동이 **요구사항과 일치**함을 단위 테스트로 증명한다.
- TDD Red–Green–Refactor 사이클에서 **회귀 방지 게이트**로 `mvn test` / `mvn verify`를 사용한다.
- JaCoCo로 **Controller 및 협력 클래스**의 라인·브랜치 커버리지를 90% 이상 유지한다.

### 1.2 테스트 범위 (In / Out)

| 구분 | In Scope | Out of Scope |
|------|----------|--------------|
| 단위 | `TVController`, `ChannelInputBuffer`, `FavoriteChannels`, `ScannedChannelList`, `ChannelConstants`, `remoteKey` 디스패치 | `Tuner` **구현체** 내부 로직 |
| 계약 | `Tuner` Mock/Fake 동작 (0~99, `seekCH` 스텁) | 하드웨어·리모컨 센서 프로토콜 |
| 참고 | `TunerTest` — Mock **계약 예시** (스텁 없으면 실패 가능) | `Item` 클래스 수정·테스트 |
| 비기능 | JaCoCo 리포트, CI에서 `verify` 실패 조건 | UI·E2E·성능·부하 |

## 4. 경계값 테스트 (채널 0, 1, 98, 99)

요구사항 **C-01**: 유효 채널 **0 ~ 99** (포함). 아래는 **키·채널 경계**를 QA 관점에서 고정하는 케이스이다.

### 4.1 채널 번호 경계 (튜너·최종 `setCH`)

| # | 시나리오 | 입력 시퀀스 / 조건 | 기대 `setCH` | 규칙 |
|---|----------|-------------------|--------------|------|
| B-CH-01 | 최소 채널 | `0` + `OK` (또는 `0` 단독 확정 규칙) | `"0"` | 0 유효 |
| B-CH-02 | 최소+1 | `1` + `OK` | `"1"` | N-01 |
| B-CH-03 | 최대-1 | `9`,`8` 연속 또는 `98` 확정 | `"98"` | 2자리 상한 내 |
| B-CH-04 | 최대 채널 | `9`,`9` 연속 → `"99"` | `"99"` | 2자리 즉시 반영 |
| B-CH-05 | 상한 순환 | ch=`99`, 검색 없음, UP | `"0"` | UD-03 |
| B-CH-06 | 하한 순환 | ch=`0`, 검색 없음, DOWN | `"99"` | UD-04 |
| B-CH-07 | 목록 경계 | 검색 {…,98,99}, ch=98, UP | 목록 내 다음 또는 순환 | UD-05 변형 |
| B-CH-08 | 선호 경계 | 선호 {0,99}, ch=50, `FAV_NEXT` | `"99"` | P-01 변형 |

### 4.2 리모컨 숫자 키 경계 (KEY_0, KEY_1, KEY_98·99 표현)

숫자 키는 `remoteKey.KEY_0` … `KEY_9`. **98·99**는 한 자리 키가 아니라 **채널 값** 경계이므로 입력 조합으로 검증한다.

| # | 키/입력 | 시나리오 | 기대 | 비고 |
|---|---------|----------|------|------|
| B-KEY-01 | `KEY_0` | `0` + `OK` | `setCH("0")` | 선행 0 vs 채널 0 구분 |
| B-KEY-02 | `KEY_0`,`KEY_1` | 연속 | `setCH("1")` | N-07 변형 (`0`,`1`→1) |
| B-KEY-03 | `KEY_1` | `1` + `OK` | `setCH("1")` | N-01 |
| B-KEY-04 | `KEY_9`,`KEY_9` | 연속 (확인 없음) | `setCH("99")` | 최대 2자리 즉시 |
| B-KEY-05 | `KEY_9`,`KEY_9`,`KEY_OK` | 99 확정 후 버퍼 클리어 | 마지막 `99` 유지 또는 재확인 무효 | OK-02 연계 |
| B-KEY-06 | `KEY_9`,`KEY_8` | 연속 | `setCH("98")` | B-CH-03 |
| B-KEY-07 | `KEY_1`,`KEY_0`,`KEY_0` | 연속 | `10` 후 `0` 또는 `100` 무효 | 3자리: `10` 반영 후 `0` 단독 — **명세 고정** |
| B-KEY-08 | `KEY_1`,`KEY_0`,`KEY_0`,`KEY_OK` | — | `0` 또는 무시 | B-KEY-07 + 확인 |

**권장 ParameterizedTest (P0~P1)**

```java
@ParameterizedTest
@CsvSource({
    "KEY_0, OK, 0",
    "KEY_1, OK, 1",
    "KEY_9|KEY_8, , 98",
    "KEY_9|KEY_9, , 99"
})
```

- 구분자는 프로젝트 컨벤션에 맞게 `@MethodSource` 사용 권장.
- **0, 1, 98, 99** 네 값은 반드시 **최종 `verify(tuner).setCH(...)`** 로 포함.

### 4.3 무효 조합 (버퍼·파싱 경계)

| # | 입력 | 기대 (Controller) | Tuner Mock |
|---|------|-------------------|------------|
| B-INV-01 | `1`,`0`,`0` → 해석 `100` | `setCH` **호출 안 함** (또는 10만 반영 — **팀 합의 1안**) | Controller는 0~99만 `setCH` |
| B-INV-02 | 확인만 | never | OK-02 |
| B-INV-03 | `9`,`9`,`9` | `99` 후 남은 `9`는 1자리 대기; `OK` 시 `9` | 버퍼 잔여 규칙 |
| B-INV-04 | 업/다운 during 버퍼 | N-06: 클리어 후 ±1 | — |

### 6.2 JaCoCo Maven 설정 (미적용 → 추가)

`pom.xml`에 JaCoCo 플러그인이 없으므로 아래를 추가한다 (Java 21 toolchain과 별개로 동작).

```xml
<properties>
    <jacoco.version>0.8.12</jacoco.version>
</properties>

<build>
    <plugins>
        <plugin>
            <groupId>org.jacoco</groupId>
            <artifactId>jacoco-maven-plugin</artifactId>
            <version>${jacoco.version}</version>
            <executions>
                <execution>
                    <id>prepare-agent</id>
                    <goals><goal>prepare-agent</goal></goals>
                </execution>
                <execution>
                    <id>report</id>
                    <phase>test</phase>
                    <goals><goal>report</goal></goals>
                </execution>
                <execution>
                    <id>check</id>
                    <phase>verify</phase>
                    <goals><goal>check</goal></goals>
                    <configuration>
                        <rules>
                            <rule>
                                <element>BUNDLE</element>
                                <limits>
                                    <limit>
                                        <counter>LINE</counter>
                                        <value>COVEREDRATIO</value>
                                        <minimum>0.90</minimum>
                                    </limit>
                                    <limit>
                                        <counter>BRANCH</counter>
                                        <value>COVEREDRATIO</value>
                                        <minimum>0.85</minimum>
                                    </limit>
                                </limits>
                            </rule>
                        </rules>
                        <includes>
                            <include>com/bestreviewer/*</include>
                        </includes>
                        <excludes>
                            <exclude>com/bestreviewer/Tuner.class</exclude>
                        </excludes>
                    </configuration>
                </execution>
            </executions>
        </plugin>
    </plugins>
</build>
```

### 6.5 `TunerTest`와 커버리지 분리

- `TunerTest`는 **Mock 기본 동작** 검증용 참고 테스트이다. 스텁 없이 실행 시 실패할 수 있다.
- **권장**: `@Tag("tuner-contract")` + `mvn test -Dgroups=controller` 또는 Surefire `excludes`로 CI 단계 분리.
- Controller 커버리지 목표는 **`TVControllerTest` + 협력 클래스 직접 테스트**만으로 달성한다.
