## 요약

**생성자 `TVController(Tuner tuner)`**  
- SRP 관점에서 **문제 없음** (DI + `processingCH` 초기화만 담당).

**핵심 이슈는 생성자가 아니라 `pushButton` / `setTunerCh` / 향후 확장 구조**입니다.

| 우선순위 | 핵심 | 이유 |
|:---:|------|------|
| **1** | `tuner.setCH` 연동, `System.out` 제거 | 핵심 동작 미구현, 로그는 테스트 불가 |
| **2** | 숫자 키 0~9 공통 처리 | case 9개 복제·Duplicated Code 예방 |
| **3** | 채널 버퍼 별도 객체 | God Class·복잡 버퍼 규칙(N-03~N-07) 격리 |
| **4** | 키 핸들러/맵 (OCP) | 업다운·선호·검색 추가 시 switch 비대화 방지 |
| **5** | 0~99 상수·검증 | Magic Number, Tuner 계약 정합 |

**SRP**: 키 라우팅 + 버퍼 + (예정) 선호/검색/튜너 제어가 한 클래스로 모이는 구조, `setTunerCh`의 로그·도메인 혼합.  
**OCP**: `switch(key)` — 키 추가마다 `TVController` 수정 필요.  
**스멜**: `setCH` 주석(Dead Code), `tuner` 미사용, `String` 버퍼(Primitive Obsession), 향후 Long Method·case 복제.

보고서에는 요청하신 **「문제점 | 위반 원칙/스멜 | 영향 | 개선 방향 | 우선순위」** 표가 §5에 정리되어 있습니다. 리팩토링은 `.cursorrules`대로 **테스트 Green 이후** 진행하는 것이 좋습니다.

## 변경 요약

### 1. `tuner.setCH` 연동 · 로그 제거
- `setTunerCh`의 `System.out` 및 주석 처리된 `setCH` 제거
- `confirmChannelFromBuffer()`에서 유효 채널(0~99)만 `tuner.setCH` 호출 후 버퍼 초기화

### 2. 숫자 키 0~9 공통 처리
- `remoteKey`에 `KEY_0`~`KEY_9` 추가, `isDigitKey()` / `getKeyValue()` 제공
- `pushButton`에서 숫자 키는 한 경로로 `channelBuffer.appendDigit()` 처리

### 3. 채널 버퍼 분리 (SRP)
- **`ChannelInputBuffer`**: 숫자 누적, 파싱, 초기화
- **`ChannelConstants`**: `MIN_CHANNEL`/`MAX_CHANNEL`, `isValid()`

### 4. OCP — 키 핸들러 맵
- **`RemoteKeyHandler`**: 함수형 인터페이스
- `EnumMap<remoteKey, RemoteKeyHandler>`로 `KEY_OK` 등록 (향후 업/다운·선호 키는 핸들러만 추가)

### 5. `TVController` 구조

```22:40:d:\Vs_workplace\Java_project\TDD_TV_01\src\main\java\com\bestreviewer\TVController.java
    public void pushButton(remoteKey key) {
        if (key.isDigitKey()) {
            channelBuffer.appendDigit(key.getKeyValue());
            return;
        }

        RemoteKeyHandler handler = keyHandlers.get(key);
        if (handler != null) {
            handler.handle(this);
        } else {
            channelBuffer.clear();
        }
    }
```

- 미등록 키: 버퍼 무효화 (`clear`) — N-06 대비
- 빈 버퍼 + 확인: `setCH` 호출 안 함

### 6. 테스트 추가
- N-01: `KEY_1` → `KEY_OK` → `verify(tuner).setCH("1")`
- 빈 버퍼 + `KEY_OK` 시 `setCH` 미호출

## 구현 내용

### 1. 숫자 채널 입력 (N-01 ~ N-07)
- **2자리 자동 확정**: `12`, `34`, `45` 등 2자리 입력 시 즉시 `setCH`
- **확인(KEY_OK)**: 버퍼 1자리(`6` 등) 확정
- **N-07**: `0` + `7` → `"07"` → 채널 7
- **N-06**: 확인·숫자 외 키 → 버퍼만 초기화 후 해당 동작 수행

### 2. 채널 업/다운
- **검색 없음**: ±1, 0↔99 순환 (UD-01~04)
- **검색 있음**: 저장 목록 기준 이전/다음·순환 (UD-05~08)

### 3. 채널 검색 (S-01)
- `seekCH()` 반복 호출로 시청 가능 채널 목록 저장 (중복 시 종료)

### 4. 선호 채널
- **FAV_ADD**: 현재 채널 선호 토글 (추가/삭제)
- **FAV_NEXT**: 현재보다 큰 최소 선호 채널, 없으면 최소값으로 로테이션 (P-01, P-02)

### 5. 추가된 `remoteKey`
`KEY_CH_UP`, `KEY_CH_DOWN`, `KEY_SEARCH`, `KEY_FAV_ADD`, `KEY_FAV_NEXT`

### 6. 신규/수정 클래스
| 클래스 | 역할 |
|--------|------|
| `FavoriteChannels` | 선호 채널 저장·다음 선호 계산 |
| `ScannedChannelList` | 검색 목록·목록 기준 업/다운 |
| `ChannelInputBuffer` | 2자리 자동 확정 + 확인 시 1자리 확정 |

### 사용 예

```java
controller.pushButton(remoteKey.KEY_1);
controller.pushButton(remoteKey.KEY_2);        // → 채널 12

controller.pushButton(remoteKey.KEY_SEARCH);   // 채널 검색
controller.pushButton(remoteKey.KEY_CH_UP);    // 목록 기준 업

controller.pushButton(remoteKey.KEY_FAV_ADD);  // 선호 토글
controller.pushButton(remoteKey.KEY_FAV_NEXT); // 다음 선호
```

`mvn test -Dtest=TVControllerTest` 로 검증할 수 있습니다. `TunerTest`는 Mock 스텁 미설정으로 기존과 같이 실패할 수 있으며, 이번 Controller 구현과는 별개입니다.
